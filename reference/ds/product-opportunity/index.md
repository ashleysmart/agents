# Product Opportunity Scout / 製品化機会の探索

## Purpose / 目的

- Turn repeated underlying needs into an evidence-backed product candidate without mistaking repetition for authorization to build.
- **Format:** agent-assisted work tool; these guides do not provision an application or execute external systems.

## Bring / 入力

- Customer requests grouped by distinct account and customer type.
- Existing product capabilities and what was configured or built each time.
- Known delivery effort, frequency, and business value evidence.

## How to run / 進め方

- **1.** Separate the request’s wording from the underlying need before grouping similar requests.
- **2.** Check whether the existing product already meets the need; route standard functionality to configuration and enablement.
- **3.** Distinguish genuinely customer-specific logic from a reusable need across independent accounts.
- **4.** Count customers, not repeated requests within one account; treat three customers as a signal to review, not an automatic build instruction.
- **5.** Estimate reuse value only from supplied inputs; show assumptions and missing data instead of inventing savings.
- **6.** Write the candidate note with need, affected customer types/count, work repeated, potential saving/value, and suggested product owner; keep the product decision separate.

## Check the result / 確認

- Classification includes evidence and uncertainty.
- Account counts represent distinct supplied accounts.
- No roadmap promise is implied by a candidate note.
