# Product Reuse And Growth — accompanying notes / 講義メモ

- **Use:** background material, separate from operational skill instructions.
- **Handling:** names and identifying details are redacted; wording is cleaned for readability.

## Written notes / 講義メモ

- Distinguish a reusable product or method from a one-customer project.
- Reuse can be knowledge, a graph, or a repeatable process rather than software alone.
- Classify delivery effort as configuration, extension, or invention.
- Classify needs as bespoke, product candidate, or already-standard functionality.
- Count shared needs across customers and assess the repeated complexity/cost.
- Know existing product behavior before claiming a request is novel.
- The deployment loop is real work → captured data/knowledge → better decisions → a next useful use case.
- Ask how current work improves a reusable foundation.
