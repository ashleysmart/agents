# Deployment Planner / 導入計画 — failure patterns / 失敗パターン

- **Use:** identify a concrete observation before applying a pattern.
- **Finding:** name the consequence and the next useful check.
- **Uncertainty:** absence of evidence is not proof that a failure occurred.

## Order-taking

- **Signal:** The plan repeats requested features without an outcome.
- **Response:** Ask which decision changes and what happens if it does not.

## Invent-first

- **Signal:** Custom work begins before checking existing capabilities.
- **Response:** Demonstrate the capability gap before choosing a build.

## Local success only

- **Signal:** The prototype works but nobody owns adoption or maintenance.
- **Response:** Identify the customer and delivery owners after launch.
