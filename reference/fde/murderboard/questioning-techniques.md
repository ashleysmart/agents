# Questioning techniques / 質問の組み立て

- **Use:** turn a broad concern into a question whose answer could change the decision.
- **Adaptation:** the claim/evidence/consequence structure is an editorial facilitation aid.

## Ask / 質問

- **Claim:** “What needs to be true for this part of the design to work?”
- **Evidence:** “What have you observed or tested that supports it?”
- **Boundary:** “Which users, cases, and conditions did that evidence cover?”
- **Counterexample:** “What happens when the source is stale or the user lacks access?”
- **Consequence:** “If this assumption is wrong, which customer decision is affected?”
- **Alternative:** “Why is this preferable to configuring the existing capability?”
- **Closure:** “What evidence would resolve this uncertainty, and who can supply it?”

## When the answer is unknown / 不明なとき

- Record what is known before describing what remains uncertain.
- Ask how the answer could be established.
- Assign an answer owner and a follow-up date when available.
- Do not reward an unsupported guess over an honest gap.

## Avoid / 避けること

- Avoid leading questions that contain the desired answer.
- Avoid several unrelated questions in one turn.
- Avoid presenting a speculative failure as an observed incident.
- Avoid checking every imaginable failure when the user requested a narrow rehearsal.
